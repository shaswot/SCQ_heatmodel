# SCQ_heatmodel

This repository contains the notebook workflows used in **Revisiting Thermal Scalability of Large-Scale Superconducting Quantum Systems**.

## Quick guide for reviewers

If you are reviewing the paper results, start here:

1. Open `notebooks/figures` to reproduce paper figures.
2. Open `notebooks/experiments` to see the underlying experiment/model runs.
3. Use `library` to inspect the shared thermal modeling implementation.

## Repository overview

- `library/`: Python modules implementing thermal/electrical model components and helper utilities.
- `notebooks/`: Jupyter notebooks for experiments, analysis, and figure generation.
	- `notebooks/experiments/`: notebooks that run full thermal model experiments.
	- `notebooks/figures/`: notebooks used to generate figures for the paper.
	- `notebooks/ler/`: notebooks for surface-code cycle simulation using `stim` and `pymatching`.
	- `notebooks/wires/`: notebooks for thermal and electrical wire modeling.

Within both `notebooks/experiments/` and `notebooks/figures/`, there are three main scenario groups:

- `directions/`: forward-looking hypothetical systems targeting 10k qubits in one fridge.
- `historical/`: reimplementations of previously published thermal scalability models.
- `solutions/`: design-space exploration for readout-amplifier submodules (amplifier $\times$ amplifier-bias wiring) from thermal-load and scalability perspectives.

These folders are further subdivided by fridge, amplifier, and related hardware configuration details.

## Files produced in experiment folders

Each experiment folder under `notebooks/experiments/` typically contains:

- `*.ipynb`: notebook that runs the thermal model.
- `*.yaml`: hardware/system configuration for the run (fridge, wiring, attenuation, and related parameters).
- `*_THL.png`: thermal heat-load breakdown visualization for the configuration.
- `*.pkl`: pandas DataFrame with detailed heat breakdown.
- `PQ_*.pkl`: pandas DataFrame with the number of physical qubits supported by each fridge temperature stage.

## Running with Docker

```bash
# clone this repo
cd SCQ_heatmodel
docker compose up -d
```

This command builds and starts the containerized environment with the following configuration (defined in `docker-compose.yml`).

- Jupyter URL: `http://localhost:1168`
- Password: `tqe` 

`run_all_notebooks.ipynb` executes all the notebooks in the repository except for the surface-code cycle simulation notebooks in `notebooks/ler`. This will take a few minutes.  
The notebooks in `notebooks/ler` can take significant time depending on your machine configuration (~2 hours in a 24-core machine).
